# Provider contracts

Verified against the sources below on **2026-09-07**. Public source and fixtures establish implementation evidence, not a stable vendor guarantee. No implementation here refreshes credentials. HTTP 401/403 becomes unavailable; other HTTP and schema failures are isolated and sanitized.

The named reference is [Paseo's quota-fetcher](https://github.com/getpaseo/paseo/tree/main/packages/server/src/services/quota-fetcher/providers). ASU independently implements its own plugin and output contracts. Where provider-owned API documentation is absent, the table explicitly distinguishes the Paseo reference from official provider sources.

Claude's configured home follows the official [`CLAUDE_CONFIG_DIR` documentation](https://code.claude.com/docs/en/env-vars), with `CLAUDE_HOME` retained as a compatibility fallback. The access token, subscription type, and rate-limit tier come from local OAuth metadata. On macOS, the `Claude Code-credentials` service is queried for the current account before the service-only legacy lookup. Both failed lookups and malformed account-specific entries can fall back.

Codex reads subscription OAuth credentials, not ordinary API keys. [Official authentication documentation](https://developers.openai.com/codex/auth/) describes its file/keyring choices; ASU implements the requested `auth.json` sources. It neither invokes login nor accesses/refreshes Codex's keyring-only sessions.

## Remaining limitations

- Only Claude, Codex, and Copilot have passed live checks, all on Linux. Other adapters have fixture coverage only. Platform-specific Keychain and desktop-store paths are not live-verified on macOS/Windows.
- Copilot's internal endpoint can expose plan-only or legacy quota data; it may not represent every newer AI-credit billing arrangement. A zero entitlement can accompany a reported 100% usage value. ASU preserves that percentage and the reported zero quantities rather than inferring actual consumed requests.
- Copilot credentials must be available through the listed environment variables or GitHub CLI `hosts.yml`. Installation/authentication through another CLI store alone does not guarantee that these sources exist.
- Claude validates additive scoped entries separately; malformed entries are omitted with a normalized warning while valid top-level windows survive.
- Cursor's individual usage endpoint is supported from the named reference, not a documented vendor contract. Unknown plan limits remain unknown.
- Z.ai can return multiple subscription records; labels and status details are retained without guessing which subscription is active. No China ZHIPU adapter is included.
- Kimi booster-wallet balances and Grok historical/on-demand spending are not normalized yet. Their supported subscription windows remain available.
- MiniMax's regional response schemas and count semantics need live confirmation. ASU rejects unrecognized hosts instead of forwarding credentials to arbitrary resource URLs.
- Tests and diagnostics never record real credential files or raw authenticated responses. No real-account fixture is committed.
